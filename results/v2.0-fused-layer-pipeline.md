# v2.0 — 融合切层流水

## 目标

把模型层分布到 RTX 3060 与 Radeon 8060S，让两端共同处理同一次 prefill。该版本关注单请求吞吐，不替代 v1.0 的独立 PD 双工定位。

## 机制

llama.cpp 上游 PR #18626 为 RPC 后端加入 events/async。prompt 的 micro-batch 依次经过两端所拥有的层：3060 处理下一批前段层时，395 可同时完成上一批后段层。权重静态驻留在所属端，流水只传递批次计算数据。

本实验使用上游能力，没有自研引擎补丁。

来源：[llama.cpp PR #18626](https://github.com/ggml-org/llama.cpp/pull/18626)

## 测量边界

- 单机 RTX 3060 12GB + Radeon 8060S
- 9B Q6_K
- pp5064 测 prefill，tg128 测 decode
- 单并发短基准

## 计算值

- Fusion-58 相较纯 3060 prefill：约 +34.0%。
- Fusion-58 相较 v1.0 完整独立 PD：约 +46.7%。
- Fusion-58 相较两端单卡 prefill 吞吐之和 2559 tok/s：约 83.2%。
- Fusion-64 decode 相较纯 395：约 +18.8%；相较 v1.0 完整 PD：约 +22.7%。

这些百分比是从表中实测值计算所得。v1.0 使用 server 请求测量，v2.0 使用 llama-bench pp/tg，因此跨版本比较仅是工程参考。

## 结论与限制

Fusion-58 是当前实测最佳 prefill 配比，证明异构按层流水可以超越任一单端。Fusion-64 的 decode 也高于纯 395 与 v1.0 PD，但低于纯 3060。

融合形态会同时占用两端，不能保留 v1.0 的请求间 prefill/decode 双工。27B、100K 上下文、多并发和多机均未验证；v2.0 仍是实验结果，不是生产部署结论。
