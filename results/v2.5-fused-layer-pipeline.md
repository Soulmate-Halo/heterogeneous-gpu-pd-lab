# v2.5 — Fused-Layer Pipeline Evolution

[简体中文](v2.5-fused-layer-pipeline.zh-CN.md)

## Objective

Distribute model layers across the RTX 3060 and Radeon 8060S so both devices contribute to one prefill. This design targets single-request throughput and does not replace v1.0's independent-PD duplex positioning.

## Mechanism

Upstream llama.cpp PR #18626 added events/async behavior to the RPC backend. Prompt micro-batches pass through the endpoint-owned layers: while the AI Max+ 395 processes the rear stage of one micro-batch, the RTX 3060 can begin the front stage of the next. Weights remain resident on their assigned endpoint; the pipeline transfers batch computation state.

Source: [llama.cpp PR #18626](https://github.com/ggml-org/llama.cpp/pull/18626)

The public revision names intentionally omit the internal layer-allocation policy.

## Measurement boundary

- One host with RTX 3060 12GB and Radeon 8060S
- 9B Q6_K
- `pp5064` for prefill; `tg128` only where recorded
- Short single-concurrency benchmark

## Derived values

- v2.5 versus RTX 3060-only prefill: +34.0%.
- v2.5 versus AI Max+ 395-only prefill: +119.6%.
- v2.5 versus the 2559 tok/s sum of both standalone prefill measurements: 83.2% efficiency.

These percentages are calculations from the table. v1.0 used server requests while v2 uses llama-bench pp/tg, so cross-release comparisons remain engineering references.

## Conclusion and limits

v2.5 proves that asynchronous heterogeneous layer pipelining can outperform either local endpoint alone. The fused form occupies both endpoints and therefore cannot preserve v1.0's cross-request prefill/decode duplex behavior. Tests have not yet covered 27B models, 100K context, concurrent load, or multiple hosts.
