# v2.5 — 稠密加速：异步分层 PD 演进

[English](v2.5-fused-layer-pipeline.md)

## 目标

把模型层分布到 RTX 3060 与 Radeon 8060S，让两端共同处理同一次 prefill。最终异步分层 PD 形态正式命名为**稠密加速**；它关注单请求吞吐，不替代 v1.0 的独立 PD 双工定位。

## 机制

llama.cpp 上游 PR #18626 为 RPC 后端加入 events/async。prompt 微批依次经过两端所拥有的层：AI Max+ 395 处理上一微批后段层时，RTX 3060 可以开始下一微批前段层。权重常驻所属端点，流水传递批次计算状态。

来源：[llama.cpp PR #18626](https://github.com/ggml-org/llama.cpp/pull/18626)

公开版本名有意隐藏内部切层策略。

## 稠密区域

**稠密区域**是异步流水时间轴上的重叠计算窗口：外接显卡与 AI Max+ 395 同时处于有效计算状态，分别处理相邻微批和各自层段。持续填满这段窗口可减少流水气泡，对其覆盖的模型层段进行强加速。它描述的是调度重叠，不代表两卡重复计算同一层、进行张量并行或重复驻留权重。

## 测量边界

- 单机 RTX 3060 12GB + Radeon 8060S
- 9B Q6_K
- `pp5064` 测 prefill；仅在有记录的节点给出 `tg128`
- 单并发短基准

## 计算值

- v2.5 相对纯 RTX 3060 prefill：+34.0%。
- v2.5 相对纯 AI Max+ 395 prefill：+119.6%。
- v2.5 相对两端单卡 prefill 实测之和 2559 tok/s：效率 83.2%。

以上百分比均由表中数据计算。v1.0 使用 server 请求，v2 使用 llama-bench pp/tg，因此跨版本对比仅是工程参考。

融合 decode 的 37.16 tok/s 记录于 v2.3；v2.5 未记录 decode，因此不作推算。

## 27B 探索验证 — 独立口径

本组使用 Qwen3.8-27B UD-IQ3_XXS（27.32B 参数、10.17 GiB、3.06 bpw），不能与 9B 主表直接比较。

| 测量项 | 纯 AI Max+ 395 | 稠密加速 | 实测变化 |
| --- | ---: | ---: | --- |
| pp4096 | 313.28 tok/s | **658.52 tok/s** | +110% |
| pp65536 | 136.69 tok/s | **319.10 tok/s** | +133%（2.33 倍） |
| pp98304 | 900 秒超时 | **225.10 tok/s** | 完成，TTFT ≈ 437 秒 |
| Decode tg64 | 18.26 tok/s | **19.57 tok/s** | 约 +7% |

本环境没有可用的 RTX 3060 单卡 27B 基线。稠密加速形态下，外接显卡只驻留分配给它的层段；内部切层比例不公开。本组是 IQ3 结果，不是 Q4 结果。

## 结论与限制

v2.5 稠密加速证明异步异构切层流水可以超过任一单端本地基线。稠密区域会同时占用两端，因此无法保留 v1.0 的多请求 prefill/decode 双工。现有证据已包含一组最长 98,304 token 的 27B IQ3 独立扫描；27B Q4、多并发与多机尚未验证。
