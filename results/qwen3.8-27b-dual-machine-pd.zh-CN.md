# Qwen3.8-27B 异构实验 — 契约化、分口径记录

[English](qwen3.8-27b-dual-machine-pd.md)

本文是本地 Qwen3.8-27B 实测的唯一人类可读权威入口。旧标签 27B-A/B/C/D 保留为别名，但它们不是四项可以直接排名的实验。

## 记录地图

| 稳定编号 | 旧标签 | 实验单元 | 证据类型 |
| --- | --- | --- | --- |
| **27B-LONG-01** | 27B-A | 3060 + 395、IQ3 长 prompt 分层驻留 | 匹配主机对照改善 |
| **27B-PD-01** | 27B-B | 3080 全量 Prefill → 395 全量 Decode 服务交接 | PD 可行性与调度包络 |
| **27B-KV-01** | 27B-C / 27B-D | 3080 全计算 + 395 KV-only；C/D 是两个配置画像 | 容量与服务包络 |
| **27B-DRAFT-AUDIT-01** | 395 自然语言审计 | 投机 Decode 的负载敏感性检查 | 验证护栏 |

## 27B-LONG-01 — 分层长 prompt 可行性

### 实验契约

| 项目 | 定义 |
| --- | --- |
| 主要问题 | RTX 3060 无法装下完整 27B 时，增加 3060 层段能否改善 395 主机的长 prompt 执行？ |
| 模型 / 口径 | Qwen3.8-27B UD-IQ3_XXS，27.32B 参数、10.17 GiB、3.06 bpw。 |
| 匹配对照 | 同模型、同量化、同 prompt 深度的 AI Max+ 395 单机。 |
| 变化因素 | 增加 RTX 3060 层段；prompt 深度另行分档。 |
| 判定指标 | 各 prompt 深度能否完成、Prefill、tg64 Decode。 |
| 结论边界 | 只支持相对匹配 395 路径的改善；不存在 3060 整模单卡对照，也不是 Q4 结果。 |

### 结果

| 负载 | AI Max+ 395 单机 | 3060 + 395 分层 | 观测变化 |
| --- | ---: | ---: | ---: |
| pp4096 | 313.28 tok/s | **658.52 tok/s** | +110% |
| pp65536 | 136.69 tok/s | **319.10 tok/s** | +133%（2.33×） |
| pp98304 | 900 秒后超时 | **225.10 tok/s** | 完成；TTFT ≈ 437 秒 |
| tg64 | 18.26 tok/s | **19.57 tok/s** | 约 +7% |

**回答：**分层路径通过长 prompt 可行性门槛，并改善匹配的 395 单机路径；由于 3060 装不下整模，不能据此声称相对 3060 整模单卡加速。

## 27B-PD-01 — 全量 Prefill / 全量 Decode 服务交接

### 实验契约

| 项目 | 定义 |
| --- | --- |
| 主要问题 | RTX 3080 Prefill 服务能否在 C1–C6 把 KV 状态稳定交给 395 Decode 服务？ |
| 模型 / 口径 | Qwen3.8-27B Q4_K_M，约 17.66 GiB，输出 255 token，KV q4_0。 |
| 主路径 | RTX 3080 CUDA0 全量 Prefill → 共享内存 KV 交接 → AI Max+ 395 Vulkan 全量 Decode。 |
| 匹配对照 | 同一请求走 395 solo。 |
| 变化因素 | router split 路径与 395 solo；并发另扫 C1–C6。 |
| 判定指标 | TTFT、Prefill、Decode、KV 迁移耗时、请求成功。 |
| 结论边界 | 历史双实例 PD 可行性；它不是后续 KV-only 架构。 |

### C1–C6 服务矩阵

斜线左/右分别为 PD / 395 solo。

| C | TTFT ms | Prefill tok/s | Decode tok/s | KV 迁移 ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | **1073 / 4825** | **1000.6 / 207.2** | 38.75 / 36.33 | 71 |
| 2 | 1680 / 9649 | 1008.4 / 103.6 | 27.94 / 24.36 | 76 |
| 3 | 2680 / 15321 | 1014.5 / 65.3 | 21.45 / 21.17 | 68 |
| 4 | 3255 / 19763 | 1010.9 / 50.6 | 18.34 / 14.44 | 72 |
| 5 | 4457 / 22460 | 1015.5 / 44.5 | 13.10 / 11.48 | 72 |
| 6 | 5009 / 22303 | 1014.3 / 44.8 | 9.67 / 8.82 | 70 |

RTX 3080 另有 pp1024 1228.53、pp4096 1203.06、tg64 33.08 tok/s 的硬件参考；它们不是上述服务路径对照的替代品。

**回答：**该实验通过状态交接与 C1–C6 服务可行性门槛。它测量的是阶段串行归属，不代表两个设备共同计算同一阶段。

## 27B-KV-01 — 远端 KV 服务画像

### 实验契约

| 项目 | 定义 |
| --- | --- |
| 主要问题 | RTX 3080 承担全部 Prefill 与 Decode、395 只存远端 KV 时，容量与服务能力如何取舍？ |
| 计算归属 | RTX 3080：全部计算；AI Max+ 395：只存 KV，不参与 Prefill 或 Decode。 |
| 配置画像 | C = Prefill 优先，D = Decode 优先；二者属于同一实验，不是两项实验。 |
| 最新匹配对照 | 未记录：没有同轮、同每流 1M 上下文的 3080 无远端 KV 序列。 |
| 变化因素 | 调度画像与 C1–C6 并发。 |
| 判定指标 | 上下文容量、Prefill、单流 Decode、聚合 Decode、缺失字段覆盖。 |
| 结论边界 | 只支持容量与服务包络。395 不贡献模型计算，因此该拓扑不是稠密加速。 |

## 27B-DRAFT-AUDIT-01 — 自然语言护栏

### 实验契约

| 项目 | 定义 |
| --- | --- |
| 主要问题 | 重复文本上的投机 Decode 高值能否代表自然语言服务？ |
| 触发证据 | 395 重复文本点测在 100% 草稿接受率下报告 35.0–38.5 tok/s。 |
| 审计负载 | 395 DFlash2 路径直发自然语言，C1/C2/C3/C4/C6。 |
| 判定指标 | 单流与聚合 Decode、接受率、每步毫秒、每步 token。 |
| 结论边界 | 这是负载敏感性审计，不是架构排名或匹配加速测试。 |

RTX 3080 的独立点测也显示负载敏感：自然语言 42.7 tok/s、接受率 43%；代码 67.4 tok/s、接受率 87%。两者只是点测，不属于下表矩阵。

| C | 单流 Decode tok/s | 聚合 Decode tok/s | 接受率 % | ms/step | tokens/step |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 12.1 | 10.9 | 17.7 | 178 | 2.17 |
| 2 | 9.9 | 16.4 | 24.3 | 262 | 2.61 |
| 3 | 7.6 | 19.3 | 21.1 | 318 | 2.42 |
| 4 | 5.8 | 19.5 | 17.9 | 378 | 2.19 |
| 6 | 4.0 | 19.8 | 18.3 | 548 | 2.22 |

**回答：**重复文本高值不能泛化到自然语言服务。生产结论必须使用自然语言审计或工作负载匹配的测试。

## 外部背景与边界

- DGX Spark 数据只保留在唯一的[社区外部对照详档](dgx-spark-community-control.zh-CN.md)。量化、引擎、KV 类型、prompt 深度和拓扑不同，不能组成受控本地排名。
- 27B-LONG-01 使用 IQ3 与 3060；其他主要记录使用 Q4 与 3080，禁止合并速率。
- 历史调度矩阵与后续纠正摘要保持为不同口径。纠正计算归属不会生成新实验，缺失并发档也不能插值。
- 机器可读来源：[qwen27b-local-results.csv](../data/qwen27b-local-results.csv)。其中按发布保存的旧标签由 [experiment-index.csv](../data/experiment-index.csv) 映射到稳定编号。
