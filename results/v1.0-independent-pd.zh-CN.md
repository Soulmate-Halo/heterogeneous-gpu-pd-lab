# 9B-PD-01 — 独立 PD 状态交接可行性

[English](v1.0-independent-pd.md)

## 实验契约

| 项目 | 定义 |
| --- | --- |
| 主要问题 | RTX 3060 完成部分或全部 Prefill 后，能否把状态交给 AI Max+ 395 继续 Decode？ |
| 假设 | 随着加速卡承担的预填充比例增加，TTFT 应下降、Prefill 应提高，交接后的 Decode 应保持连续。 |
| 匹配对照 | AI Max+ 395 单机；使用同一 9B Q6_K 模型与 5064 输入 / 128 输出请求。 |
| 变化因素 | 交接前由 RTX 3060 预填充的 prompt token：0、前 512、前 2048、完整 prompt。 |
| 主要指标 | 请求完成、TTFT、Prefill、Decode、迁移状态大小。 |
| 通过边界 | 完整 PD 请求成功、交接可归属，且 Decode 在本轮波动范围内没有实质退化。 |
| 不能证明 | 两端同时计算、并发服务吞吐，以及对其他模型或量化的泛化。 |

## 测量边界

- 模型：9B，Q6_K
- 负载：5064 输入 token，128 输出 token
- 测量：关闭缓存；保留服务端第二次请求结果
- 设备：RTX 3060 / CUDA Prefill 路径，AI Max+ 395 / Radeon 8060S / Vulkan Decode 路径

## 结果

| 配置 | 加速卡预填充范围 | TTFT | Prefill | Decode | 交接量 |
| --- | --- | ---: | ---: | ---: | ---: |
| AI Max+ 395 单机 | 无 | 5.879 s | 861.55 tok/s | 30.24 tok/s | — |
| 部分 PD | 前 512 token | 5.720 s | 886.62 tok/s | 30.22 tok/s | 512 token |
| 部分 PD | 前 2048 token | 5.077 s | 999.16 tok/s | 30.18 tok/s | 2048 token |
| 完整独立 PD | 完整 prompt | **3.496 s** | **1452.29 tok/s** | **30.28 tok/s** | 5063 token / 208.57 MiB |

## 回答

该实验通过可行性门槛：完整 CUDA-Prefill → Vulkan-Decode 交接成功；相对匹配的 395 单机请求，TTFT 与 Prefill 改善，Decode 保持在同一窄幅区间。两端仍按阶段先后执行，因此它只是后续并发稠密区域的前置证据，不是并发计算证据。

机器可读来源：[benchmark-results.csv](../data/benchmark-results.csv)，筛选 `architecture=independent-pd`。
